# iOS Picture in Picture Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development for the two
> independent components below, then integrate and review the complete change.

**Goal:** Keep movies and episodes playing in native iOS PiP on app backgrounding.
**Architecture:** One VLC decoder feeds an inline sample-buffer platform view and
Apple PiP; native code owns background transitions, Dart exposes existing controls.
**Tech Stack:** Flutter/Dart, Swift, AVKit, MobileVLCKit 3.7.3.
**Spec:** ../specs/2026-09-19-ios-pip.md

## Global constraints
- No decoder/source replacement on PiP entry or exit.
- iOS app minimum 15.6; plugin minimum 13 with API availability guards.
- Preserve Android/macOS/Windows/Linux renderer and background defaults.
- Pause in background if PiP fails; user pause/close must not auto-resume.
- Native frame handoff must be bounded and never queue all decoded frames.
- Existing Apple signing configuration, no new dependencies or credentials.

## Task 1: Flutter integration
Files: player_platform_service.dart, vlc_player_screen.dart, settings_dialogs.dart,
their tests; packages/vlc_player/lib/src/vlc_player.dart and vlc_player_config.dart,
package widget tests.

Interface: VlcDarwinRenderer.sampleBuffer selects UiKitView on iOS and passes
creationParams `pictureInPicture: true`. Other creation paths omit that field.
The iOS PiP channel is `vlc_player/pip`; Android remains unchanged. Both accept
`enterPip` with isPlaying/videoWidth/videoHeight and `setPipState` with the same
payload, and send `pipModeChanged` with bool. iOS transport delegates stay native.

## Task 2: Native iOS PiP and background policy

VlcPlayerPlugin.swift integration; ios/Runner/Info.plist audio mode.

Use the existing textureRenderer for decoded frames and getMediaInfo/snapshot
state for timing. `enterPip` returns completion from actual AVKit delegate result.
